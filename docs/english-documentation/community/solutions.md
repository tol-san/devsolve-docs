# Write and manage Solutions

<a href="/km/community/solutions" class="button secondary">ខ្មែរ</a>

A Solution is an answer to a specific Problem. It should be reproducible and explain why the approach works.

{% hint style="info" %}
**Available to:** Signed-in users who are not the Problem author  
**Navigation:** Open a Problem → choose the answer/Solution action
{% endhint %}

## Choose an approach

| Approach | Meaning |
| --- | --- |
| Fix | Removes the cause |
| Workaround | Avoids the issue without removing the cause |
| Explanation | Explains the behavior without changing code |
| Alternative | Proposes a different route |

## Write a Solution

1. Enter a one-line summary of 10–250 characters.
2. Write an explanation of at least 30 characters using Markdown where helpful.
3. Select the approach type.
4. Add verification steps with the expected result for each step.
5. Record the technologies and versions used for testing.
6. Explain trade-offs, limitations, or costs.
7. Add supported resources—documentation, repository, video, diagram, demo, or article—and optional attachments.
8. Review the readiness list and submit.

All resource URLs must use `https://`. Write examples with placeholder secrets and safe sample data.

## After submission

The Solution can be pending review, approved, or rejected. Rejected Solutions remain visible to their author with available review information but are not presented as normal public answers. Open **My Community** to manage your Solutions. You can edit only your own Solution.

When the Problem author or supported workflow accepts a Solution, it becomes the accepted answer and the Problem can be shown as solved.
