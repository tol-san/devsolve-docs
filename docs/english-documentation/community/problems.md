# Create and manage Problems

<a href="/km/community/problems" class="button secondary">ខ្មែរ</a>

A Problem asks the public Community for help with a technical issue.

{% hint style="info" %}
**Available to:** Signed-in users  
**Navigation:** **Community → Start a discussion → Problem & Bug**
{% endhint %}

## Choose the correct Problem type

| Type | Use it for |
| --- | --- |
| Bug | Incorrect behavior you can demonstrate |
| How-to | A known goal without a clear implementation path |
| Architecture | A system structure or component-boundary question |
| Performance | Software that works too slowly or expensively |
| Security | A safe hardening or authentication question suitable for public discussion |
| Deployment | Builds, pipelines, environments, and releases |
| General | A technical issue outside the other types |

## Create a Problem

{% stepper %}
{% step %}
### Describe the Problem

Enter a clear title of 10–180 characters, select a category and Problem type, and write a useful description of at least 30 characters.
{% endstep %}

{% step %}
### Add technical context

Add technologies and versions, repository URL, environment, severity, and SDLC phase when relevant. Repository links must use `https://`.
{% endstep %}

{% step %}
### Add evidence

For a Bug, provide expected behavior, actual behavior, and at least one reproduction step. You can also add error output, previous attempts, and attachments.
{% endstep %}

{% step %}
### Check similar Problems

Review duplicate suggestions. Open a similar item before publishing when it may already answer your question.
{% endstep %}

{% step %}
### Organize and submit

Choose existing tags or add allowed new tag names, review the readiness checklist, then save a Draft or submit for approval.
{% endstep %}
{% endstepper %}

## Manage the Problem

Open **Dashboard → My Community** to see your Problem and its review state. You can edit it only when ownership and status rules allow. Published Problems collect Solutions, votes, comments, and views. Marking an accepted Solution can resolve the Problem; a Problem can also be closed when discussion should end.

See [Community review and statuses](moderation-and-statuses.md) for the complete lifecycle.
