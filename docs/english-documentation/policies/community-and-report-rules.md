# Community and report-quality rules

<a href="/km/policies/community-and-report-rules" class="button secondary">ខ្មែរ</a>

## Community content

- Use descriptive titles and enough context to be useful.
- Search for duplicates before posting.
- Credit sources and link to them safely.
- Keep comments focused on the technical topic.
- Do not publish secrets, credentials, personal data, harassment, spam, or uncoordinated vulnerability details.
- Explain code and sanitize logs or screenshots.

## Problems

Choose the correct type and category. For Bugs, include expected behavior, actual behavior, and reproduction steps. Record the environment and versions when they affect the outcome.

## Solutions

State whether the answer is a fix, workaround, explanation, or alternative. Include verification, tested versions, trade-offs, and source links where they add confidence.

## Showcases

Publish work you are allowed to share. Explain the project’s purpose, steps, technology stack, and external resources. Do not use a Showcase to expose private customer or vulnerability information.

## Vulnerability Reports

Confirm Scope, describe impact, provide reproducible evidence, avoid destructive payloads, remove real personal data, and follow the Program’s disclosure rules.
